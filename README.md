# 홈바 플랫폼

**집에 있는 술로 지금 뭘 만들 수 있는지** 계산해 주는 모바일 우선 웹앱.
재료를 체크하면 칵테일 202종을 즉시 대조해 **정규 · 근사 · 부족**으로 갈라주고,
한 병 더 사면 몇 종이 열리는지, 내 취향엔 뭐가 맞는지, 위스키 컬렉션에 뭐가 비었는지까지 계산한다.

서버·계정·설치 없이 브라우저에서 돌아간다. 입력한 건 전부 **내 브라우저에만** 저장된다.

> **아직 정식 공개 전이다.** 자동 배포는 꺼져 있고, 올릴 때만 Actions 에서 직접 실행한다.
> 내부 확인용 `beta` 빌드에는 **오너의 홈바(보유 주류 82종·재고 69종)가 들어 있다.**
> 링크를 받은 사람은 아무거나 눌러봐도 된다 — 바꾼 값은 각자 브라우저에만 저장되고 원본은 그대로다.
> 정식 공개판(개인 데이터 제외)은 프로필만 바꿔 배포한다. [배포 프로필](#배포-프로필) 참고.
>
> 게시하면 앱은 `https://squarekim.github.io/homebar/`, 레거시 단일 파일 앱은 `.../homebar/legacy/` 로 열린다.

**같이 개발하려면 → [CONTRIBUTING.md](CONTRIBUTING.md)** (세팅 10분, 아키텍처 지도, 작업 규칙, 열려 있는 과제)

## 이럴 때 쓴다

| 상황 | 어디서 | 뭘 얻나 |
|---|---|---|
| 오늘 뭐 마시지 | 홈 → **오늘 뭐 마실까** | 달달한/상큼한/강한/가벼운 기분별 추천 + 지금 바로 되는 것만 필터 |
| 이거 만들 수 있나 | 홈바 → **칵테일** | 레시피별 정규·근사·일부부족·불가와 **뭐가 없어서 안 되는지** |
| 뭐 사지 | 추천 → **구매** | 재료 하나 살 때 **추가로 열리는 레시피 수**로 순위화 |
| 친구가 옴 | 추천 → **그룹** | 여러 명 취향을 합쳐, 한 명이라도 싫어하는 향미는 감점해서 추천 |
| 술 새로 삼 | 아무 화면 **우하단 +** | 이름만 검색 → 분류·도수·용량·원산지·칵테일 재료까지 자동 등록 |
| 위스키 뭐 살까 | 위스키 → **축별 결손** | 지역×숙성 매트릭스와 축 커버리지에서 **비어 있는 칸** + 구매 시뮬레이터 |
| 마신 거 기록 | 어디서나 **기록하기** | 서빙 스타일·평점·향미 평가 → 취향 프로필 자동 갱신 |

## 5분 시작하기

1. **재고 맞추기** — 홈바 → **재고**. `전부 해제`를 누르고 집에 있는 것만 체크한다. 체크할 때마다 상단 숫자가 바로 바뀐다.
2. **술 등록** — 우하단 **+** 버튼. `발베니 12`, `조니블랙`, `Absolut`처럼 대충 쳐도 찾아준다. 고르면 분류·도수·용량·원산지가 자동으로 채워지고, 칵테일 재료로도 켜진다.
3. **마셔보고 기록** — 추천 카드나 레시피에서 `기록하기`. 몇 잔 쌓이면 취향 프로필이 자동으로 잡히고 추천 정확도가 올라간다.

상단 숫자 4개(정규·근사·불가·보유재료)는 **눌러보면 뜻이 뜬다.**

## 화면별로 뭘 하나

### 홈
오늘 마실 것 추천(기분별 6가지 필터), 바로 제조 가능한 칵테일, 최근 기록, 추천 구매를 한 화면에 모았다.
추천 카드마다 **점수와 이유**가 같이 나온다 — 취향 적합도·재고 활용도·가용성·신선도를 결합한 값이다.

### 홈바 🍸 — 칵테일 중심
- **칵테일** — 202종 검색·필터(상태/기주/IBA). 카드를 누르면 재료별 보유 여부, 부족한 재료, 대체 조주 여부, 향미 프로파일, 출처가 나온다.
- **재고** — 재료 128종 체크. `잔량 표시`를 켜면 병별 남은 양(%)까지 관리한다.
- **재료** — 재료별 레시피 활용 횟수. 뭘 먼저 살지 감 잡을 때 쓴다.

### 위스키 🥃 — 니트로 마시는 술 중심
- **컬렉션** — 보유 위스키를 원산지·타입·지역·캐스크·캐릭터로 분류해 배지로 보여준다. 태그를 **누르면 용어 해설**이 뜬다(셰리 캐스크가 뭔지, 피티드가 뭔지).
- **제조사 공식 노트** — 보유 주류 **38종**(위스키 22종 포함)에 공식 사이트 기준 테이스팅 노트를 **출처 URL과 함께** 붙였다. 개인 시음 메모도 병별로 따로 적는다.
- **축별 결손** — 지역×숙성 매트릭스(엔트리/스탠다드/고숙성 18+)와 축 커버리지에서 **비어 있는 칸**을 실시간 계산한다.
- **구매 시뮬레이터** — 후보 위스키를 넣어보면 기존과 **겹치는 축**과 **새로 여는 축**을 산출한다. "또 셰리 스페이사이드 사는 거 아닌가"를 사기 전에 확인.

### 추천 ✨
- **칵테일/위스키** — 취향 14축 기반. 코사인 유사도로 계산하고 점수와 이유를 같이 준다.
- **그룹** — 사람을 여러 명 등록해 함께 마실 것을 고른다. 평균이 아니라, 한 명이라도 강하게 싫어하는 향미가 센 술에 **패널티**를 준다.
- **재고 소진** — 잔량이 얼마 안 남은 재료를 먼저 쓰는 레시피를 올려준다(홈바 재고에서 잔량을 입력해 두면 동작).
- **구매** — 재료 하나를 샀을 때 **구매 전/후 제조 가능 수와 증가분**, 열리는 레시피 이름, 취향 적합도를 함께 보여준다.

### 프로필 👤
취향 14축 슬라이더(수동 조정 또는 기록에서 자동 도출), **그룹 인원 등록**(그룹 추천용), 음용 통계, 음용 기록 전체, **JSON 백업/복원**.

## 알아두면 편한 3가지

**1. 판정 4단계**

| 상태 | 뜻 |
|---|---|
| **정규** | 필수 재료를 전부 보유, 대체 없이 원 레시피대로 |
| **근사** | 필수 재료는 다 있지만 일부를 대체재로 충당 |
| **일부부족** | 부재료가 빠짐 (기주는 있음) |
| **불가** | 기주 등 핵심 재료가 없음 |

`(선택)` 표기 재료는 판정에서 제외한다. 판정은 **재고 데이터로만** 계산한다 — 레시피 설명문은 판정에 관여하지 않는다.

**2. 제품이 아니라 표준 재료로 매칭한다**

```
봄베이 사파이어 ┐
탱커레이       ├→ 표준 재료 '런던 드라이 진' → 진토닉 · 네그로니 · 마티니 …
비피터         ┘
```

무슨 브랜드를 넣든 같은 표준 재료로 해석되므로 레시피가 똑같이 열린다.
술을 추가할 때 이 연결이 자동으로 맺어진다(원하면 다이얼로그에서 다른 재료로 바꿀 수 있다).

**3. 취향 14축**

단맛 · 스모크 · 피트 · 과일 · 바닐라 · 카라멜 · 오크 · 스파이스 · 플로럴 · 허브 · 시트러스 · 견과 · 초콜릿 · 바디 (각 0~10).
추천 엔진은 **외부 AI 없이** 이 벡터만으로 동작한다.

## 내 데이터는 어디에 있나

- 재고·기록·취향·메모·추가한 술은 전부 **내 브라우저(IndexedDB)** 에만 저장된다. 서버로 가지 않는다.
- 기기를 옮기거나 백업하려면 **프로필 → JSON 백업**으로 파일을 받고, 새 기기에서 **복원**하면 된다.
- 브라우저 데이터를 지우면 같이 지워진다. 중요한 기록은 주기적으로 백업할 것.
- 베타 링크를 여러 명이 열어도 서로 영향이 없다. 각자 브라우저에 각자 상태가 쌓인다.
- **설치**: 모바일 브라우저의 `홈 화면에 추가`를 누르면 앱처럼 쓸 수 있다(PWA, 오프라인 동작).

## 개발

```bash
cd app
npm install
npm run dev           # 개발 서버 (beta 프로필)
npm run build         # 타입체크 + 빌드(dist/) — 오너 데이터 포함
npm run build:public  # 공개 배포 빌드(dist-public/) — 개인 데이터 제외
npm test              # 단위 테스트(vitest)
```

React 18 + TypeScript + Vite + Dexie(IndexedDB) + PWA. 추후 Capacitor 로 Android APK 래핑 가능한 구조.

### 배포 프로필

| | beta (기본) | public |
|---|---|---|
| 레시피 202 · 재료 128 · 믹서 · 주류 마스터 275 | 포함 | 포함 |
| 오너 보유 주류 82종 · 개인 재고 69건 | **포함** | **번들에서 제외** |
| 첫 화면 | 오너 컬렉션 그대로 (정규 105) | 기본 홈바 세트 41종 (정규 79) |

`.github/workflows/deploy-pages.yml` 은 **수동 실행 전용**이다(정식 공개 전이라 push 트리거를 꺼 뒀다).
올릴 때 Actions 탭 → `Deploy to GitHub Pages` → **Run workflow** → 프로필 선택.
공개 단계로 넘어가면 워크플로 상단의 `push:` 블록 주석을 풀면 `main` 푸시마다 자동 배포된다.
Pages 소스는 **Settings → Pages → Source = `GitHub Actions`** 로 이미 지정돼 있다.

공개 프로필은 `scripts/makePublicSeed.mjs` 가 만든 `seed.public.ts` 를 vite 플러그인이 원본 대신 물려 빌드한다.
**원본 `seed.ts` 는 수정하지 않는다.**

### 구조

| 계층 | 위치 | 역할 |
|---|---|---|
| 시드/파생 | `app/src/data` | 원본 데이터(읽기 전용) + 파생(향미 렉시콘·ID·ml 파싱·분류·용어·주류 마스터) |
| 모델 | `app/src/models/types.ts` | 도메인 타입 |
| 저장소 | `app/src/db` | Dexie. 사용자 상태만 저장 |
| 리포지토리 | `app/src/repositories` | UI/서비스가 DB를 직접 호출하지 않도록 격리 (Supabase 등 교체 대비) |
| 서비스 | `app/src/services` | 판정·추천·그룹·구매·취향·검색·백업 (UI와 분리된 순수 로직) |
| UI | `app/src/ui` | 하단 5탭 + 전역 추가 버튼 |

시드 변환이 필요하면 손으로 고치지 않고 `app/scripts/` 의 스크립트로 일괄 처리한다
(`cleanRecipeNotes.mjs` — 레시피 note 의 "특정 사용자 재고" 문장 제거. 판정은 `ingredientId × 재고`로만 계산되므로 중복이었다).

## 레거시 단일 파일 앱

루트의 `index.html` 은 `홈바_마스터_가이드_V54.xlsx` 에서 생성한 단일 파일 웹앱이다.
